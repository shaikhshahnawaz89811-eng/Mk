# CodeAssistAI

Dark glassmorphism AI code-assistant chat app for Android (Kotlin, XML views).

## v2.2 — real pipeline (no more dummy replies)
- **No canned answers.** Chat, code snippets and project edits are generated by the loaded
  Gemma model. If no real model is bound the app says so and shows the exact reason
  (Models screen + chat) instead of inventing a reply.
- **Code tasks are real and guarded.** Snippet requests use the active Coder Helper in strict
  code-only mode. Project edits use Gemma planning -> Implementation Contract -> Coder ->
  Patch Guard -> atomic patch apply -> deterministic validation -> Gemma review. The old
  unguarded direct model-write path and `ASSISTANT_PLAN.md` filler are gone.
- **New projects** start from a deterministic scaffold, then model-written implementation uses the same two-module coding pipeline when the Coder Helper is imported. Without the helper, the app does not pretend the starter scaffold is a completed model-generated implementation.
- **Coder Helper** is a real, user-imported model: Models → Coder Helper → Import / Delete.
  Project implementation is two-module only: Gemma plans/analyzes/reviews, Coder writes code.
  Gemma hands Coder a structured contract; Patch Guard validates the entire patch before any write;
  Gemma is restored before the helper is released; and failed bounded attempts roll back to the
  initial filesystem checkpoint. Duplicate-file import is rejected by content hash.
- **Header** stays "CodeAssistAI" — it no longer turns into the first message.
- Chat keeps the last turns of the conversation as context for follow-ups.

## What's new in v1.1 (polish pass)
- **ChatGPT / Claude style navigation**: bottom bar removed — a side drawer
  (hamburger, top-left) now holds New chat, Chats, Projects, Settings and
  your recent chats.
- **In-place chat**: sending a message on home no longer pushes you to
  another screen — the greeting fades away and the conversation happens
  right there. Existing chats from the drawer / Chats screen also open
  in-place.
- **No more refresh jumps**: the active chat is persisted; leaving the app
  and coming back (or process death) restores the exact same conversation.
  `singleTask` launch mode prevents duplicate/restarted screens.
- **Smart scroll**: new messages auto-scroll only while you're near the
  bottom; scrolling up locks position and shows a jump-to-bottom button.
  Keyboard open/close keeps the latest message pinned above the composer.
- **Predictable back**: drawer closes first, tab screens return home,
  back on a chat returns to the greeting, then exit.
- **Visual consistency**: removed the broken center chips (Create Project /
  Upload File / Get Help), unified composer focus glow with the theme,
  matched the system nav bar to the app background, calmer user bubble,
  plain full-width AI messages, pulsing "Thinking..." indicator, subtle
  150–200 ms animations everywhere.

## Features
- Screens: Home/Chat (unified), Chats, Projects, Settings, Create Project
  modal, Project Workspace, Skill Loading & Error state
- Glass cards, glowing accents, animated skill-loading arc
- Chat composer: grows to 5 lines then scrolls internally, 4000-char limit
  with live counter, send disabled past the limit
- Attachments: images <= 10 MB, zip/files <= 25 MB, max 5 files / 50 MB
  total, chips with remove
- Local persistence (SharedPreferences + Gson). All data stays on device.

## Build
```
./gradlew assembleDebug
```
The coding pipeline produces a source ZIP in Artifacts. Per the mobile delivery policy, the on-device coding pipeline does not launch a Gradle build daemon.
It performs deterministic Android structure/static checks and records that build execution is deferred;
GitHub Actions performs the real Gradle unit-test/lint/assemble verification.

## CI
GitHub Actions workflow: `.github/workflows/android-build.yml` builds debug + release APKs and uploads them as artifacts.
